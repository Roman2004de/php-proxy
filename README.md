# PHP Proxy

Прокси принимает адрес ресурса в параметре `url`, переписывает ссылки в HTML, CSS, JavaScript и SVG и передаёт остальные ответы без изменений тела. Для доступа нужны HTTPS, учётная запись и настроенный список целевых origin.

## Развёртывание

1. Установите PHP 8.2+ с расширением cURL, актуальным libcurl и системным набором доверенных CA. Разместите `run.php` и `lib/` в каталоге приложения. Публичной точкой входа служит `run.php`. Укажите веб-серверу фактический document root.
2. Выделите отдельное HTTPS-имя для каждого разрешённого upstream origin. Настройте DNS, сертификаты и виртуальные хосты. Используйте выделенные имена без других приложений и отклоняйте неизвестные имена хостов. В конфигурации PHP за балансировщиком или reverse proxy выставляйте `HTTPS=on` только для соединений, защищённых доверенным TLS-терминатором, и передавайте `Authorization` в PHP. Для сырого тела multipart-запросов установите `enable_post_data_reading=Off` на уровне выделенного PHP-пула.
3. Создайте каталог состояния вне document root и каталога приложения. Владелец должен совпадать с пользователем PHP, права — `0700`. Настройте следующие переменные в окружении PHP.

| Переменная | Значение |
| --- | --- |
| `PHP_PROXY_ORIGINS` | JSON-объект вида `{"https://example.com":"https://example.proxy.example.net/run.php"}`. Ключ включает схему, имя и нестандартный порт, если он есть. Используйте нижний регистр и ASCII/Punycode. Каждый endpoint требует уникального имени хоста. |
| `PHP_PROXY_USERS` | JSON-объект вида `{"alice":"<хеш пароля>"}`. Создавайте хеши функцией PHP `password_hash($password, PASSWORD_DEFAULT)`. |
| `PHP_PROXY_STATE_DIR` | Абсолютный путь к закрытому каталогу cookie jars и счётчиков. |
| `PHP_PROXY_REQUESTS_PER_MINUTE` | Лимит запросов на учётную запись в минуту. По умолчанию 240. |
| `PHP_PROXY_MAX_RESPONSE_BYTES` | Лимит тела ответа upstream в байтах. По умолчанию 32 МиБ, максимум 256 МиБ. |

Генерация хеша из стандартного ввода без записи пароля в историю команд

```sh
read -rs proxy_password
printf '%s' "$proxy_password" | php -r 'echo password_hash(stream_get_contents(STDIN), PASSWORD_DEFAULT), PHP_EOL;'
unset proxy_password
```

Откройте `https://example.proxy.example.net/run.php?url=https%3A%2F%2Fexample.com%2F` и введите логин и пароль в браузере. Для CLI можно использовать `curl --user alice URL`. Добавьте на веб-сервере ограничение частоты до PHP для запросов к публичному endpoint, включая запросы без авторизации, и ограничение размера входного тела. При обновлении старого развёртывания закройте прямой доступ к прежнему каталогу `cookies/`. Новые сессии создаются при следующем входе.

## Поведение HTTP и браузера

- Прокси проверяет DNS-ответы и закрепляет проверенный IP в cURL. Переход по `Location` создаёт отдельный запрос к соответствующему endpoint со своей проверкой. Для исходящего HTTPS проверяются цепочка сертификатов и имя хоста.
- Лимит входного тела составляет 2 МиБ. Бинарные ответы буферизуются в памяти до 1 МиБ и затем во временном файле. Переписывание текста использует до 2 МиБ входа и допускает до 8 МиБ результата. Частичные ответы, ответы с нестандартной для переписывания кодировкой UTF-16/32 и upstream-ответы со сжатием, несмотря на запрос `Accept-Encoding: identity`, передаются с исходным телом.
- Прокси сохраняет политики CSP, X-Frame-Options и Cross-Origin-* от upstream. Строгий CSP может заблокировать встроенный JavaScript для Fetch/XHR, правила с исходными именами хостов могут заблокировать переписанные адреса, а SRI может отклонить ресурс после его переписывания.
- Браузер хранит Basic-аутентификацию отдельно для каждого хоста. Дополнительный домен ресурса может потребовать свой вход. Между origin доступны только чтение и OPTIONS, когда браузер уже отправляет авторизацию, и запросы проходят политику CORS исходного сайта. Стандартный CORS-preflight без авторизации получает 401. При межсайтовых запросах серверная сессия upstream не передаётся.
- Cookie jars изолированы по пользователю, сессии и upstream origin. Браузерная cookie действует 30 дней. В закрытом каталоге состояния можно периодически удалять файлы `jar-*` старше 31 дня вместе с их файлами блокировки, пока PHP-пул остановлен.
