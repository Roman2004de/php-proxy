# PHP Proxy

Прокси принимает адрес ресурса в параметре `url`, переписывает ссылки в HTML, CSS, JavaScript и SVG и передаёт остальные ответы без изменений тела. Ссылка открывается сразу. Для работы нужны HTTPS и настроенный список целевых origin.

## Развёртывание

1. Установите PHP 8.2+ с расширением cURL, актуальным libcurl и системным набором доверенных CA. Для развёртывания скопируйте `proxy.php` в каталог приложения. Укажите веб-серверу фактический document root.
2. Выделите отдельное HTTPS-имя для каждого разрешённого upstream origin. Настройте DNS, сертификаты и виртуальные хосты. Используйте выделенные имена без других приложений и отклоняйте неизвестные имена хостов. В конфигурации PHP за балансировщиком или reverse proxy выставляйте `HTTPS=on` только для соединений, защищённых доверенным TLS-терминатором. Передавайте в `REMOTE_ADDR` адрес клиента, определённый доверенным веб-сервером. Для сырого тела multipart-запросов установите `enable_post_data_reading=Off` на уровне выделенного PHP-пула.
3. Разрешите PHP обрабатывать `PATH_INFO` для пути `/proxy.php/_form/…`. Веб-сервер должен передавать суффикс от `/_form/` в `PATH_INFO`, а имя скрипта оставлять `/proxy.php`. Этот маршрут сохраняет адрес назначения при отправке GET-форм.
4. Создайте каталог состояния вне document root и каталога приложения. Владелец должен совпадать с пользователем PHP, права — `0700`. Настройте следующие переменные в окружении PHP.

| Переменная | Значение |
| --- | --- |
| `PHP_PROXY_ORIGINS` | JSON-объект вида `{"https://example.com":"https://example.proxy.example.net/proxy.php"}`. Ключ включает схему, имя и нестандартный порт, если он есть. Используйте нижний регистр и ASCII/Punycode. Каждый endpoint требует уникального имени хоста. |
| `PHP_PROXY_STATE_DIR` | Абсолютный путь к закрытому каталогу cookie jars, ключа подписи сессий и счётчиков. Ключ создаётся автоматически. |
| `PHP_PROXY_REQUESTS_PER_MINUTE` | Лимит запросов в минуту на IPv4-адрес или IPv6-сеть /64. По умолчанию 240. |
| `PHP_PROXY_GLOBAL_REQUESTS_PER_MINUTE` | Общий лимит запросов в минуту на каталог состояния. По умолчанию 2400. |
| `PHP_PROXY_MAX_COOKIE_STORAGE_BYTES` | Лимит суммарного размера файлов cookie jars. По умолчанию 16 МиБ, максимум 256 МиБ. |
| `PHP_PROXY_MAX_SSE_SECONDS` | Максимальная длительность одного SSE-соединения. По умолчанию 300 секунд, максимум 3600. |
| `PHP_PROXY_MAX_RESPONSE_BYTES` | Лимит тела ответа upstream в байтах. По умолчанию 32 МиБ, максимум 256 МиБ. |

Пример публичной ссылки

`https://example.proxy.example.net/proxy.php?url=https%3A%2F%2Fexample.com%2F`

При обновлении замените путь на `/proxy.php` в конфигурации веб-сервера, `PHP_PROXY_ORIGINS` и сохранённых ссылках. Закройте прямой доступ к старому каталогу `cookies/`. Ограничение частоты и размера входного тела на веб-сервере позволяет отклонять избыточный трафик до запуска PHP.

## Поведение HTTP и браузера

- Прокси проверяет DNS-ответы и закрепляет проверенный IP в cURL. Переход по `Location` создаёт отдельный запрос к соответствующему endpoint со своей проверкой. Для исходящего HTTPS проверяются цепочка сертификатов и имя хоста.
- Лимит входного тела составляет 2 МиБ. Бинарные ответы буферизуются в памяти до 1 МиБ и затем во временном файле. Переписывание текста использует до 2 МиБ входа и допускает до 8 МиБ результата. Частичные ответы, ответы с нестандартной для переписывания кодировкой UTF-16/32 и upstream-ответы со сжатием, несмотря на запрос `Accept-Encoding: identity`, передаются с исходным телом.
- Прокси сохраняет политики CSP, X-Frame-Options и Cross-Origin-* от upstream. Строгий CSP может заблокировать встроенный JavaScript для Fetch/XHR, правила с исходными именами хостов могут заблокировать переписанные адреса, а SRI может отклонить ресурс после его переписывания.
- Для запросов из другого origin доступны чтение и OPTIONS по правилам CORS исходного сайта. Такие запросы не используют серверную сессию upstream.
- SSE (`text/event-stream`) передаётся по мере поступления. Прокси передаёт `Last-Event-ID` при переподключении. При достижении лимита времени или тела поток закрывается. Для SSE отключите буферизацию в промежуточных прокси и задайте таймауты PHP-FPM и веб-сервера с учётом выбранного лимита.
- Cookie jars изолированы по браузерной сессии и upstream origin. Браузерная cookie действует 30 дней. Файл cookie jar создаётся, если upstream установил cookie. При работе с сессиями прокси автоматически удаляет файлы без изменений за 30 дней. Хранилище вмещает до 4096 файлов по 64 КиБ каждый в рамках общего лимита. При заполнении прокси сохраняет существующие сессии и пропускает записи, которые превысили бы лимит.

Проверка регрессий

```sh
php tests/regression.php
```
